00物理引擎到底是什么

一句话：物理引擎是一个接收"力"、输出"位置与朝向"的循环。它不关心你怎么渲染，也不关心玩家按了什么键 —— 它只负责让物体动起来，并且动得"看起来对"。

先破一个常见的幻想：游戏物理引擎不是科学仿真。科学仿真追求"与真实世界一致到小数点后几位"，游戏物理追求的是在 16.6 毫秒内算完、看起来可信、绝不许炸。Millington 在开篇就明确点出这一点 —— 引擎里大量参数（阻尼系数、迭代次数、穿透容差）都是"手感调出来的"，不是物理常数。

→
输出位置 + 朝向
→

为什么需要它？

没有物理引擎的日子里，游戏里所有运动都是手写关键帧动画或硬编码脚本：箱子被打飞就播一段动画，石头落地就播一段动画。这在"只有一种情况会发生"时很好用，但一旦玩家能自由交互，组合数就爆炸了 —— 你不可能为"箱子以 37° 角撞到斜坡再弹到木桶上"预先做一段动画。

物理引擎的价值就在于：用一套统一的规则，覆盖所有你没预料到的情况。

一句话记住

物理引擎 = 用可预测的数值方法，替换掉无穷无尽的动画。它的产出不是"正确的物理"，而是"可信的运动"。

它的优缺点，得先说清楚

✓ 优点
  • 玩家交互的组合爆炸被自动覆盖
  • 美术资产可复用：同一个箱子在哪都自然
  • 行为可调：改几个参数就换手感
  • 涌现式玩法（物理谜题、可破坏场景）
✗ 缺点
  • CPU 开销大，且不可预测（最坏情况会掉帧）
  • 难调试：一个抖动的箱子可能源于十处参数
  • 美术失去精确控制（动画师会很痛苦）
  • 数值不稳定时会"炸"，而炸的方式很吓人
实践建议

商业项目里最常见的做法是混合：主角用动画/状态机控制（精确、可预测），环境与道具交给物理（自然、可交互），两者用"运动学刚体"衔接 —— 主角是 Kinematic Body，能推动别人但不会被别人推倒。

01三种实现方案与取舍

在动手之前，Millington 先摊开了一张选择表。引擎的设计其实就三个维度的取舍：模拟什么对象、怎么解决碰撞、碰撞用冲量还是用力。

维度一：对象类型

粒子
Particle —— 只有位置，没有体积和朝向。最便宜，适合烟、火、火花、水花。
质体
Mass-Aggregate —— 一堆粒子用弹簧/杆连起来。布料、绳索、软体、可破碎物体。
刚体
Rigid Body —— 有体积、有朝向、会旋转。箱子、车轮、飞船。游戏里的主力。
关节
Joint / Ragdoll —— 刚体 + 约束。布娃娃、门铰链、链条。

维度三：冲量 vs 作用力

02粒子数学：向量与积分

粒子是引擎里最简单的东西 —— 一个位置、一个速度、一个质量，没了。但它是整本书的地基：后面刚体的平动部分和粒子一模一样，只是多挂了一套旋转。

先记住三个向量运算

整本书 80% 的数学都落在这三个运算上。Cyclone 里它们的运算符重载长这样（core.h）：

为什么点积这么重要

后面碰撞求解里反复出现的分离速度 v_sep = (v₀ − v₁) · n，本质就是"相对速度在法线方向上的投影"。两辆车迎面撞 vs 追尾，差别全在这个点积的符号和大小上。

积分：把加速度变成位置

物理只告诉我们加速度（F = ma），但渲染要的是位置。从加速度走到位置，这步叫积分。游戏里用得最多、也最朴素的是半隐式欧拉（Semi-implicit Euler）：

① 位置更新 p ← p + v·Δt ② 加速度 a ← acceleration + forceAccum · (1/m) ③ 速度更新 v ← v + a·Δt ④ 阻尼 v ← v · damping^Δt ⑤ 清空累加器 forceAccum ← 0 // 对应 Cyclone src/particle.cpp:25-47
注意这个"半隐式"

先用旧速度更新位置，再用新加速度更新速度。这比"先更新速度再更新位置"的显式欧拉稳定得多 —— 显式欧拉会让弹簧和轨道运动能量发散（越摆越高，最后飞出去）。半隐式欧拉虽然也不守恒能量，但它是辛的，长期行为不会跑偏。这一行代码的顺序，决定了你的引擎会不会炸。

为什么存"质量的倒数"？

Cyclone 里 Particle 和 RigidBody 都存 inverseMass 而不是 mass。源码注释给了两个理由：

  1. 省除法：a = F/m 变成 a = F × (1/m)，积分热路径上只有乘法。
  2. 能优雅表达"无限质量"：inverseMass = 0 就是不可动物体（地面、墙）。而 mass = ∞ 在浮点里是要溢出的。源码原话："在实时仿真里，拥有无限质量（不可动）比拥有零质量（数值上完全不稳定）有用得多。"

这条设计在整本书里反复受益 —— 所有接触到 1/m 的公式，遇到静态物体时那一项自然变成 0，不需要任何 if 分支。

03运动定律与积分算式

牛顿三定律在游戏引擎里的落地版本，其实只有一个公式在干活。这一章要把"力 → 运动"这条链路彻底钉死。

牛顿第二定律，引擎版本

F = m · a // 教科书 a = F · (1/m) // 引擎里真正写的样子 动量 p = m · v 冲量关系 J = Δp = m · Δv → Δv = J · (1/m)

由此得出粒子引擎里唯一需要实现的动力学：把所有力累加起来，除以质量，乘上时间步长，加到速度上。就这么简单。

重力：唯一一个"不走累加器"的力

有意思的细节：Cyclone 里重力既可以做成力发生器（ParticleGravity，施加 F = m·g），也可以直接写进 acceleration 字段。后者更省 —— 因为 F = m·g 除以 m 又变回 g，重力产生的加速度与质量无关，这也是伽利略比萨斜塔实验的结论。

为什么"轻重同时落地"

因为 a = F/m = m·g/m = g。质量约掉了。引擎里把重力放进 acceleration，正是利用了这一点 —— 一次赋值，对所有物体生效，且与质量无关。

一帧的完整顺序

STEP 1
清空 / 施加力 —— 注册表遍历所有力发生器，各自往目标粒子的 forceAccum 里加力
STEP 2
积分 —— 每个粒子调用 integrate(Δt)：更新位置、速度、阻尼，清空累加器
STEP 3
生成接触 —— 遍历所有接触生成器（缆绳、杆、地面…），把违规的约束写进接触数组
STEP 4
求解接触 —— ContactResolver 迭代 N 轮，逐个用冲量解决
STEP 5
渲染 —— 用最新位置画出来
图 5 · ParticleWorld::runPhysics() 一帧主循环（对应 pworld.cpp:77-94）

值得注意的是 STEP 3 和 STEP 4 的顺序：先让所有物体自由运动一步，然后再检查有没有穿模、有没有把绳子拉断，最后统一修。这种"先预测，后修正"的思路贯穿全书 —— 包括后面的刚体碰撞也是这个套路。

阻尼：一个"乘以小数"的把戏

阻尼用来模拟空气阻力、能量损耗，并顺手让系统收敛。Cyclone 的实现极简：

v ← v · damping^Δt // damping = 0.99 时，每帧保留 99% 的速度 // 用 ^Δt 而不是直接乘，是为了让阻尼效果与帧率无关

为什么是 damping^Δt 而不是 v *= damping？因为后者在 30fps 和 60fps 下衰减速度差一倍，游戏换个机器手感就变了。取幂之后，无论 Δt 多大，每秒衰减比例恒定。

反直觉点

阻尼虽然叫"阻力"，但它不是力，不进累加器，也不受质量影响。它是积分器最后一步的乘法。这意味着：一个 1kg 的球和一个 1000kg 的球，用同样的 damping 会同时停下来 —— 这在真实世界里是错的，但在游戏里往往正是你想要的手感。

这一章把前三章的东西组装起来，做两个能跑的 demo。它们是理解"粒子引擎够不够用"的最佳标尺。

一个炮弹，给定初速度、发射角和质量，算它落在哪。三种发射类型：

一个初学者常问的问题

"为什么炮弹质量不同，轨迹却一模一样？" —— 因为重力加速度 g 与质量无关（见上一章）。质量在这里唯一的作用是：炮弹撞到别的东西时，产生多大的冲量。飞行过程中它完全隐身。

示例二：焰火

焰火是粒子引擎的经典展示：一个"母体"升空，到达顶点后炸成几十个小火花，每个火花各自受重力、各自带阻尼、各自淡出。

规则 1
焰火由若干"载荷"（payload）组成 —— 每个载荷有自己的类型、颜色、寿命
规则 2
载荷可以被"引爆" —— 到期后在原地生成 N 个子粒子
规则 3
子粒子继承母体的速度 + 一个随机方向的速度增量（球面均匀采样）
规则 4
子粒子受重力 + 阻尼，寿命结束后从场景移除

这一章的收获

粒子引擎能做出很炫的效果，但有个硬伤：它没有体积，所以永远不会"撞"到任何东西。焰火穿过墙壁、火花穿进地板 —— 要做真正的碰撞，就必须引入有形状的物体。这就是第二部分刚体的起点。

05合力：D'Alembert 原理与力发生器

当力越来越多 —— 重力、风、弹簧、浮力、引擎推力 —— 你不可能为每个组合写一段代码。这一章给出一个清爽的解法：力发生器 + 注册表。

D'Alembert 原理：一句话版本

核心思想

"所有力可以各自独立计算，然后简单相加。" 你不需要知道别的力存不存在 —— 每个力发生器只看自己关心的那点信息（重力只看质量，阻力只看速度），算出自己的那份力，往累加器里一扔就完事。

这个原理让物理引擎的代码彻底模块化：加一个新力 = 写一个 updateForce() 函数 + 注册一下。这也正是 Cyclone 里"数据与逻辑分离"的体现 —— 力是数据（注册表里的一条记录），力的计算是逻辑（一个可复用的类）。

硬弹簧为什么会炸，以及假弹簧怎么救

这是本章最有实战价值的一段。想做一根"几乎不可拉伸"的绳子，直觉是把 k 调得很大。但 k 越大，同样的形变产生的力越大，在离散时间步下：力大到一步就把粒子弹过头，下一步反向弹得更多 —— 系统发散，粒子飞出宇宙。

图 9 · 硬弹簧的数值爆炸：同样的物理，仅仅因为 k 太大就完全崩溃

FakeSpring（假弹簧）的思路是：既然弹簧的运动方程有解析解（阻尼简谐振动的闭式解），那就别用数值积分去逼近它了，直接把粒子放到解析解算出来的位置上。

γ = ½·√(4k − c²) target = [p·cos(γΔt) + c·sin(γΔt)] · e^(−½·c·Δt) a = (target − p)/Δt² − v/Δt F = m·a // 结果：多硬的弹簧都不会炸，因为它根本不走"力→加速度"那条路
什么时候用假弹簧

需要刚性连接但又要一点点弹性反馈时 —— 比如相机跟随、角色手臂的柔性摆动、UI 的弹性质感。它牺牲了严格的物理正确性（力不再守恒），换来的是绝对不会炸。游戏开发里这种交易几乎总是划算的。

06弹力：弹簧、蹦极与软体

弹簧是物理引擎里的"万能胶"。它既能做悬挂、绳索、布料，也能做软体、果冻、可变形物体 —— 区别只在于你怎么连。

胡克定律，以及它的三种变体

胡克定律 F = −k · x // x 是形变量 弹簧 F = −k·(‖d‖ − L₀)·d̂ // 拉伸和压缩都产生力 蹦极绳 ‖d‖ > L₀ 时才有力 // 只拉不推，像绳子 刚性杆 |‖d‖ − L₀| 都要修正 // 下一章，且不用力来做

用弹簧搭出软体

把一堆粒子用弹簧连成网格，就得到了可变形的软体。这是"质体物理引擎"（Mass-Aggregate）的基础，下一章的布料、破碎都建立在此之上。

陷阱：弹簧网格也会炸

网格里每个粒子被多个弹簧同时拉扯，等效刚度是各弹簧之和，很容易超过数值稳定上限。解决方案有三种：① 降低 k 并加阻尼（最简单）；② 用假弹簧；③ 改用下一章的硬约束，直接限制长度而不是用力去拉。

07硬约束：缆绳与杆

这一章是全书第一个"思维跃迁"：有些约束，不该用力来实现，而该用冲量。

为什么弹簧做不好"杆"

想做一根刚性杆（长度永远不变）。用弹簧近似？那你得把 k 调到无穷大 —— 结果就是上一章的爆炸。就算不炸，杆也会被"拉长一点点再弹回来"，玩家能看出来。

Millington 给出的解法非常聪明：不施加任何力。每帧检查一次几何约束，超了就生成一个"接触"，让通用求解器用冲量瞬间把它拉回来。

→

Rod: L ≠ length
→

→
冲量求解瞬间修正速度 + 位置

两种约束的行为

约束拉伸时压缩时弹性系数现实类比
Cable 缆绳生成接触，拉回来不生成接触，自由靠近用户设定（有弹性）绳子、吊索

这个设计的优雅之处

缆绳、杆、碰撞、关节 —— 它们共用同一套接触求解器。物理引擎里没有"缆绳专用代码"，只有一个通用的"两个东西违反了某个沿法线的约束，请用冲量修正"机制。这是本书最重要的架构思想之一：把约束统一表达成接触。

09旋转的数学：四元数与惯性张量

刚体比粒子多的那部分，全在这一章。很多人卡在这里不是因为难，而是因为没搞清为什么非要四元数。先回答这个"为什么"，公式就好记了。

朝向的三种表示法

表示法用几个数优点致命问题
欧拉角
Yaw/Pitch/Roll		3 个直观，人能读懂万向锁：某个角度到 90° 时丢一个自由度，物体突然卡住不能转
旋转矩阵9 个变换向量快，无奇异占内存；数值漂移后会"非正交"，需要不断重新正交化
四元数4 个无万向锁、插值平滑、只需归一化就能修正漂移不直观，人类看不懂 (r,i,j,k) 代表什么角度
万向锁到底是怎么回事

用欧拉角描述飞机朝向：先偏航（Yaw），再俯仰（Pitch），最后滚转（Roll）。当俯仰角达到 ±90°（机头垂直朝天或朝地）时，偏航轴和滚转轴重合了 —— 两个不同的操作产生了完全相同的效果，你丢失了一个自由度。飞机在这一瞬间无法做出你期望的转向。
四元数用 4 个数表示 3 个自由度（多出来的一个是冗余），从根本上绕开了这个问题。

四元数：只需要记住四件事

你不需要理解四元数的代数结构，只要记住它在引擎里的四个用法：

①
表示朝向：q = (r, i, j, k)，必须保持单位长度才是合法旋转 → 定期 normalise()
②
角速度更新朝向：q̇ = ½ · ω ⊗ q。Cyclone 里写成 addScaledVector(ω, Δt)
③
旋转一个向量：把局部坐标的向量转到世界坐标（机翼方向、锚点位置都靠它）
④
转成矩阵：渲染和惯性张量变换都需要矩阵，四元数能一键转出 3×3 旋转矩阵
图 15 · 四元数在引擎里的四个职责

关键区分

源码注释里有一句话点破本质："角速度和角加速度可以正确地用向量表示，只有朝向才需要四元数。" —— 也就是说，ω 是普通的 Vector3，只有 orientation 是 Quaternion。别把角速度也变成四元数，那是新手常见的过度设计。

惯性张量：转动的"质量"

平动时 F = ma，质量 m 是一个数。转动时 τ = I·α，但这里的 I 是一个 3×3 矩阵 —— 因为物体绕不同轴转起来的"费劲程度"不一样。

用一根棍子感受一下

拿起一根长棍：绕长轴旋转（像转笔）非常轻松；绕垂直于长轴的方向旋转（像挥棒）明显更费力。同样的质量，不同方向的转动惯量差了几十倍 —— 这就是惯性张量存在的意义。它是一个对角矩阵时（长方体等对称形状），三个对角元素就是绕 X/Y/Z 三轴的转动惯量。

形状绕 X 轴绕 Y 轴绕 Z 轴
长方体（半边长 hx,hy,hz）⅓·m·(hy²+hz²)⅓·m·(hx²+hz²)⅓·m·(hx²+hy²)
实心球（半径 r）0.4·m·r²（三轴相同，所以球怎么转都一样）

为什么存"逆惯性张量"，以及它怎么跟着物体转

和质量一样，Cyclone 存的是逆张量 I⁻¹。好处同样是两条：省一次矩阵求逆、能表达"无限惯量"（零矩阵 = 不可旋转）。

但有个新问题：物体会转，转过之后惯量就变了。一根棍子横着和竖着，绕同一个世界轴的转动惯量完全不同。解决办法是每帧做一次变换：

I⁻¹_body局部系，建模时算好
→
R · I⁻¹ · RᵀR 来自四元数
→
I⁻¹_world世界系，直接用

这里有个漂亮的数学结论

(R·I·Rᵀ)⁻¹ = R·I⁻¹·Rᵀ。也就是说：先求逆再变换，和先变换再求逆，结果完全一样。引擎因此可以只在建模时求一次逆，之后每帧只做两次矩阵乘法 —— 零次求逆。这是本书里最优雅的一处性能优化。

10刚体运算定律：力矩

这一章解释一个日常现象：为什么推箱子的边缘它会转，推正中间它就只会滑走。答案就一个叉乘。

力矩 = 力臂 × 力

τ = r × F // r 是从质心指向作用点的向量 α = I⁻¹_world · τ ω ← ω + α·Δt
推质心 → r = 0
叉乘为 0，τ = 0
→ 只有平动，箱子滑走

同理：如果 r 与 F 平行（沿着质心方向推/拉），叉乘也是 0
推边缘 → r ⊥ F
叉乘最大，τ 最大
→ 平动 + 旋转，箱子翻倒

r 越远、F 越大、夹角越接近 90°，力矩越大

副翼是怎么让飞机滚转的

左右机翼各有一个 Aero 力发生器。向左压杆时，左副翼和右副翼朝相反方向偏转，于是两边用不同的气动张量插值 —— 一侧升力增大、另一侧减小，升力差 × 力臂 = 滚转力矩。

14碰撞处理：冲量求解

这是全书技术含量最高的一章，也是"物理引擎感"的来源。目标很朴素：两个物体撞上了，它们之后的速度该是多少？

第一步：算分离速度

先判断这次碰撞"有多严重"。核心量是分离速度（separating velocity）—— 两个物体沿接触法线方向靠近或分离的速度：

v_sep = (v₀ − v₁) · n v_sep > 0 → 正在分离，不用管（它们已经在分开了） v_sep < 0 → 正在靠近，需要冲量 v_sep = 0 → 相对静止（比如静止堆叠），也不用管

第二步：算需要多大的冲量

我们希望碰撞后的分离速度变成 −e · v_sep（e 是弹性系数）。于是速度改变量是：

目标： v'_sep = −e · v_sep 需要的改变： Δv = v'_sep − v_sep 冲量大小： g = Δv / (1/m₀ + 1/m₁) // 粒子版，pcontacts.cpp:76 施加： v₀ ← v₀ + n · g · (1/m₀) v₁ ← v₁ − n · g · (1/m₁) // 注意减号：动量守恒

如果 1/m₀ + 1/m₁ ≤ 0（两个都是无限质量的静态物体），直接返回 —— 除数会炸。这也印证了前面"存倒数"设计的好处：静态物体那一项自然为 0。

刚体版多了什么

刚体会在接触点产生力矩，所以分母不再是简单的 1/m₀ + 1/m₁，而是要把"绕接触点转动的等效惯量"也算进去：

g = [(I₀⁻¹(r₀×n)) × r₀]·n + 1/m₀ + [(I₁⁻¹(r₁×n)) × r₁]·n + 1/m₁

多出来的那项 [(I⁻¹(r×n)) × r]·n 读作："如果沿着法线推这个物体，它在接触点会产生多少位移"。接触点离质心越远，这项越大，物体越倾向于旋转而不是平动 —— 这就是为什么打在箱子角上它会翻滚。

第三步：修正穿透

冲量只改了速度，物体还嵌在一起。必须把它们分开。原则是按质量比例分配位移：

总惯量 M = (1/m₀ + 1/m₁) 位移 Δx₀ = +n · (penetration / M) · (1/m₀) Δx₁ = −n · (penetration / M) · (1/m₁) // 轻的让得多，重的让得少 —— 卡车撞小车，小车被推开 // 若 1/m = 0（静态物体），它的位移自动为 0，地面纹丝不动

刚体还要处理旋转位移：把物体沿法线挪开，可能一部分该由"平移"完成、一部分该由"绕接触点旋转"完成。Cyclone 按各自的等效惯量比例分配，并且给旋转量加了个上限（默认 0.2 倍），防止出现"物体被旋转得飞出去"的诡异画面 —— 超出部分补给平移，保证总分离量不变。

第四步：为什么要迭代

一个箱子同时接触地面和另一个箱子。解决接触 A 会改变接触 B 的状态，解决 B 又破坏了 A。单次求解不可能让所有接触同时满足。

15静态接触与摩擦力

前面讲的是"撞上去又弹开"。但游戏里更常见的是静止接触：箱子放在地上、球停在斜坡上。这时候决定成败的是摩擦。

先解决一个反直觉的问题：静止的箱子为什么不下沉

每帧重力给箱子一个向下的速度，地面接触把它弹回来。如果弹性系数 e 不为 0，箱子会永远在微微跳动 —— 这是物理引擎最经典的"抖动"bug。

解法：低速时关掉弹性

Cyclone 的做法：如果分离速度的绝对值小于 0.25，就把有效弹性系数 e_eff 强制设为 0。低于这个阈值，物体之间就是纯非弹性碰撞 —— 不弹，安静地贴着。
这个小小的阈值，是"堆叠稳定"和"永远抖动"的分界线。

还有一处更精细的处理：重力补偿。求解接触时，要考虑"这一帧重力还会给它多少速度"，如果目标速度已经包含了这部分补偿，物体就不会因为"重力给它速度 → 求解器再消掉"而抖动。desiredDeltaVelocity 里的 velocityFromAcc 项就是干这个的。

摩擦：库仑模型

游戏里用的摩擦模型极其简单，一句话：摩擦力最大不超过 μ × 法向力。

|f_tangential| ≤ μ · f_normal // 在冲量世界里： 切向冲量的模 √(j_y² + j_z²) ≤ μ · j_x
图 30 · 摩擦锥：算出来的冲量如果跑出锥外，就把它拉回锥面

算法实现就是一次截断：先当没有限制算出冲量 j，如果切向分量太大，就保持方向不变、把长度缩到 μ·j_x：

planar = √(j_y² + j_z²) 若 planar > μ · j_x： (ĵ_y, ĵ_z) = (j_y, j_z) / planar // 只需方向 j_x = desiredDeltaVelocity / (D₀₀ + μ·(D₀₁·ĵ_y + D₀₂·ĵ_z)) j_y = μ · j_x · ĵ_y j_z = μ · j_x · ĵ_z
参考：常见摩擦系数

原书附录 B 给了实测参考值。几个常用的：冰-冰 0.05、木头-木头 0.4、橡胶-混凝土 0.7~1.0、金属-金属（润滑）0.15。游戏里通常会往上调一点，因为真实摩擦系数下物体"太滑"。
μ > 1 是完全合法的（比如橡胶轮胎），尽管中学物理常说 μ < 1 —— 那只是简化。

各向异性摩擦：一个高级技巧

有些物体在不同方向上摩擦不同 —— 最典型的是车轮：滚动方向摩擦小（能滚），侧向摩擦大（不打滑）。做法是把摩擦系数写成一个 2×2 矩阵（在切平面内），而不是一个数。原书提到这个技巧，Cyclone 源码里没有实现，但赛车游戏几乎都会做。

关于"允许一点点穿透"

新手总想让穿透为 0。但这是做不到的，也不该追求：位置修正本身是"硬拽"物体，拽多了会引入能量，反而制造抖动。正确做法是留一个允许穿透容差（slop） —— 比如 0.01~0.05 个世界单位，在这个范围内不修正。玩家完全看不出来，系统却稳定得多。

一句行业共识

"宁可让物体轻微重叠，也不要让它们抖动。" 玩家对"穿透 1 厘米"几乎无感，但对"箱子在地面上颤动"极其敏感 —— 后者会立刻让人觉得"这游戏很廉价"。

2D 物理的几个特殊之处

第 2 版专门加了 2D 内容，因为休闲游戏和手游的爆发。2D 相比 3D 简化明显：

  • 朝向从四元数退化成一个角度 θ（标量）—— 旋转数学全没了
  • 惯性张量退化成一个标量 —— 不用矩阵变换了
  • 叉积退化成标量（a × b = ax·by − ay·bx）—— 力矩计算变成一次乘减
  • 碰撞检测只需处理 圆、线段、多边形 三类图元

所以 2D 物理引擎的代码量通常是 3D 版本的 1/5 左右，而且更容易稳定。

Impulse 冲量瞬间改变速度的量，Δv = J/m踢一脚（而不是一直推）
Restitution 弹性系数e，0 = 完全不弹，1 = 完全弹性篮球 vs 湿泥巴
Friction 摩擦系数μ，切向冲量上限是 μ × 法向冲量冰面 vs 橡胶垫
Friction Cone 摩擦锥冲量必须落在以法线为轴、半角 arctan μ 的锥内斜着推太狠就会滑
Sleeping 休眠静止物体跳过模拟以省 CPU没人动它，就别算它
Warm Starting 热启动用上一帧的冲量作为本帧迭代初值从上次的结果接着调
CCD 连续碰撞检测防止高速物体一帧穿过薄墙连拍而不是单张快照
Gimbal Lock 万向锁欧拉角在某角度丢失一个自由度两个旋钮突然变成同一个

D源码勘误与避坑

读 Cyclone 源码（github.com/idmillington/cyclone-physics）时会撞到这些坑。它们不影响学思路，但会浪费你半天时间。

位置问题
body.cpp — hasFiniteMass()写成 inverseMass >= 0，导致无限质量的静态物体也返回 true。应为 > 0
contacts.cpp — 构造函数四参数版本的 ContactResolver 只把第一个迭代数传进去，positionIterations 形参被吞掉
contacts.h — isValid()把 positionEpsilon 检查了两遍，velocityEpsilon 根本没检查
fgen.cpp — 浮力部分浸没公式缺括号：/ 2 * maxDepth 应为 / (2 * maxDepth)，且分子符号应为 + maxDepth
fgen.cpp — Explosion空函数体。爆炸是原书的练习题，需要自己实现
fgen.h — AngledAero只有声明没有实现
ForceRegistryremove() / clear() 只有声明，全仓库无定义 —— 调用会链接失败
core.h — setBlockInertiaTensor系数写成 0.3，理论值应为 1/3
body.cpp — _transformInertiaTensor形参 const Quaternion &q 未被使用（实际用的是 orientation）
整个仓库没有四叉树 / 八叉树实现，只有包围球 + BVH 模板。书里讲的内容需要自己补
别试着把它编译跑起来

作者已多年不更新代码、不回应 issue，依赖的 OpenGL/GLUT 环境在现代系统上很折腾。建议：只读代码学思路，配合仓库里提供的 Windows 可执行文件看效果。 或者更好 —— 照着思路自己重写一遍 2D 版本，那个过程本身就值回票价。

能看出 hasFiniteMass() 写错、能发现构造函数吞掉参数 —— 说明你真的懂了。把这份勘误表当成阅读理解测验，看你能独立找出几条。
