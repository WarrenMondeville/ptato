00Verlet 到底是什么

一句话：Verlet 是一种"不存速度"的积分方法 —— 速度被隐含在"上一帧位置"里。它 1967 年由法国物理学家 Loup Verlet 为分子动力学提出，2001 年被 Thomas Jakobsen 写进《Advanced Character Physics》（初代《Hitman》的布娃娃技术），从此成为游戏物理的主力方案。

传统欧拉积分，每个粒子存两个量：

x' = x + v·Δt // 位置用速度推 v' = v + a·Δt // 速度用加速度推（a = F/m）

位置 Verlet 只存位置，但存两份（当前 x、上一帧 x*）：

x' = 2x − x* + a·Δt² // 注意：式子里没有 v x* = x

就这么点差别，换来三件事，它们构成了整个 Verlet 体系的地基：

① 稳定

它是二阶、辛（symplectic）积分器：能量不会单调增长，只在真值附近有界振荡。显式欧拉是一阶，能量稳定地往外跑。

② 约束好做

速度由位置差隐式决定，所以直接改位置就能满足约束，速度自动跟着变，不需要任何额外簿记。

③ 便宜

每粒子每帧几次加减乘。没有矩阵、没有雅可比、也没有"弹簧刚度"这种需要反复试的参数。

它和 PBD 的关系

Position Based Dynamics（PBD，Müller 2007）= Verlet 风格的位置积分 + 迭代投影约束。今天 Blender 的布料节点、大量手游里的布料与头发、Unity 生态里的软体方案，底层都是 PBD 或它的改进版 XPBD。所以学 Verlet，就是在学现代实时物理的主流骨架。

01欧拉的困境：能量从哪来

先看对手。显式欧拉的问题不是"算错一点点"，而是算错的方向永远是同一个方向 —— 系统能量一路单调递增，直到炸掉。

考虑最常见的场景：一个质点被弹簧拴在中心做圆周运动（布料里每个节点局部上就是这么个东西）。设劲度系数 k、半径 R，初始给一个正好等于 √k · R 的切向速度，理论上它应该画一个完美的圆。

下面是真实模拟。左边用显式欧拉（forward Euler），右边用位置 Verlet，完全相同的初始条件、同样的弹簧。拖动时间步滑块看看：

蓝 = 位置 Verlet，红 = 显式欧拉。读数栏显示各自的机械能 E/E₀（初始能量归一为 1.00）。注意：切换步长时代码会按新 Δt 重标定 Verlet 的历史位置，否则隐式速度会突变 —— 这正是第 11 节说的"Verlet 假设 Δt 恒定"。

把时间步拖到 1/30 以上，红色那个会明显向外螺旋，半径越转越大，最后撞墙乱飞；蓝色的轨道只是轻微进动，能量始终锁在 1.0 附近。

为什么会这样

欧拉的更新 x' = x + v·Δt 用的是这一步开始时刻的速度，而实际上速度在这一步里已经变了。在圆周运动中，这个误差恰好总是偏向切线外侧 —— 每一步都往外多走一丁点，误差同向累积，能量就单调上升。

图 1 · 同一初始条件下的两种积分器：欧拉把系统能量一路推向爆炸，Verlet 让它围着真值打转
别冤枉了半隐式欧拉

注意一个常见的混淆：把更新顺序反过来 —— v += a·Δt 再 x += v·Δt —— 得到的半隐式欧拉（symplectic Euler）其实也是辛积分器，能量同样有界，很多商业引擎（包括 Box2D 系列思路）用的就是它。真正会螺旋发散的是这里演示的显式欧拉（先用旧速度走位置）。稳定与否，差别就在那一行代码的顺序。

关键认知

游戏物理里"炸掉"几乎总是能量注入导致的：弹簧越硬 → 需要的时间步越小 → 60 FPS 下必然越界。用弹簧模拟"不可拉伸的绳"是条死路，因为绳子要"无限硬"，而无限硬的弹簧需要无限小的时间步。

02位置 Verlet：公式与三行代码

把 x(t+Δt) 和 x(t−Δt) 各自做泰勒展开，然后加起来 —— 一次项消掉、三次项也消掉，剩下的就是 Verlet。这个推导值得亲手走一遍，因为误差的性质全写在里面。

x(t+Δt) = x(t) + ẋ·Δt + ½·ẍ·Δt² + (1/6)·x⃛·Δt³ + O(Δt⁴) x(t−Δt) = x(t) − ẋ·Δt + ½·ẍ·Δt² − (1/6)·x⃛·Δt³ + O(Δt⁴) // 把 Δt 换成 −Δt 两式相加： x(t+Δt) + x(t−Δt) = 2x(t) + ẍ·Δt² + O(Δt⁴) 整理： x(t+Δt) = 2x(t) − x(t−Δt) + a·Δt² // ẍ = a

三个信息量：

  • 一次项和三次项被完全抵消 —— 局部截断误差是 O(Δt⁴)，这比欧拉的 O(Δt²) 高两个数量级。
  • 全局误差是 O(Δt²)（局部 O(Δt⁴) 累积 T/Δt 步后降两阶），所以它是二阶方法。
  • 速度根本没出现 —— 它不是"被忽略"了，而是被位置历史替代了。
图 2 · Verlet 的几何直觉：把"上一帧走过的位移"再走一遍，然后加上这一帧的加速度贡献

代码：三行，真的就三行

function integrate(p, dt) {          // p = {x, y, px, py}
  const vx = p.x - p.px, vy = p.y - p.py;  // ① 隐式速度（位移形式）
  p.px = p.x;  p.py = p.y;                 // ② 历史前移
  p.x += vx + ax * dt * dt;                // ③ 位移 + 加速度项
  p.y += vy + ay * dt * dt;
}

注意第 ③ 行的量纲：a·Δt² 是位移，不是速度。写成 a·Δt 是新手最常见的 bug —— 那样加速度的效果会和帧率挂钩，30 FPS 和 120 FPS 表现完全不同。

初始化：它不是自启动的

Verlet 需要上一帧的位置，所以第一帧必须手动造一个。给初速度 v₀ 时：px = x − v₀·Δt，这样第一帧的隐式速度 (x − px)/Δt 正好等于 v₀。忘了这一步，物体会以两倍速或零速起步。

阻尼：改一个数字就行

把位移项乘一个略小于 1 的系数 d，能量就按可控速率耗散，不需要单独的"速度阻尼 pass"：

x' = x + (x − x*)·d + a·Δt² // d = 0.99 轻阻尼，0.98 明显黏滞，1.0 无耗散

空气阻力、布料的内摩擦、绳子的手感，全靠这一个数。这也是 Jakobsen 原文里提到的技巧（把 2 换成 1.99）。

03隐式速度：稳定性从哪来

Verlet 里速度不是一个独立变量，而是被定义出来的：v ≡ (x − x*)/Δt。这个"被动速度"带来两个决定性好处。

好处一：位置和速度不可能失步

欧拉里 x 和 v 是两个各自演化的量。一旦碰撞求解器改了 v 却忘了同步 x（或者反过来），物体就会"看起来在地面下方但速度朝上"这类诡异状态。Verlet 里改位置就是改速度 —— 它们物理上是同一个存储，不存在失步。

好处二：碰撞响应免费

粒子陷进地面了？把它直接挪出来即可。下一帧的隐式速度自动变成"远离地面"，法向分量被清零。这就是所谓投影式碰撞响应（projection），对应的恢复系数恰好是 0（完全不弹）。

图 3 · 投影式碰撞：改的是位置，速度作为副产品被自动修正

想要弹跳怎么办：改 x*

恢复系数 e（0 = 泥巴，1 = 超弹球）在 Verlet 里通过反写历史位置实现。碰地瞬间，设当前法向位移速度为 vₙ：

// 碰撞：先投影，再决定"历史位置"放在哪 y = ground; // ① 推出穿透 py = y + vy * e; // ② 反写历史 → 下帧速度 = −e·vy px = x - vx * (1 - friction); // ③ 切向乘摩擦

因为下一帧速度 = (y − py)/Δt = −e·vy，符号翻转正是反弹。不用碰速度变量，因为没有速度变量。

一句话记住

在 Verlet 世界里，位置是唯一的真相，速度是一个随时可以重算的观测量。想改变运动，就去改位置（或历史位置）。

代价：别忘了它是二阶而非万能

  • 对简谐振子，稳定条件是 ω·Δt < 2（ω = √(k/m)）。超过就会指数发散 —— Verlet 只是把这个门槛抬高了，不是取消了。
  • 变时间步会破坏辛性质。要么固定步长（推荐），要么用第 11 节的 TCV 修正。
  • 它不是能量守恒，是能量有界。加上约束投影后仍会有缓慢漂移，长跑场景需要额外阻尼。

04距离约束与 Jakobsen 松弛

绳子不该用弹簧。Jakobsen 的做法是把它当成一条几何命令："这两个点必须正好相距 d"。不给力，不给刚度，只给事实 —— 然后直接把点挪到满足为止。

一个约束的投影

两点 a、b，静止长度 rest，当前距离 d（注意画布坐标 y 向下）：

delta = b − a dist = |delta| diff = (dist − rest) / dist // 归一化误差：正=太长，负=太短 a += delta · diff · (wa / (wa + wb)) // 按逆质量的反比分配修正 b −= delta · diff · (wb / (wa + wb))
图 4 · 距离约束投影：误差沿连线方向分摊，分摊比例由逆质量 w = 1/m 决定

为什么要存"逆质量"而不是质量

  • 除法变乘法：w = 1/m 一次算好，循环里只用乘。
  • 固定点就是 w = 0：不需要 if 分支，"无限重"自然表达。钉住绳子一端、钉住布料顶边、抓住玩家的手 —— 全是同一个操作。
  • 两个都是固定点（wₐ + w_b = 0）时要跳过，否则除以零。

松弛（relaxation）：一帧扫很多遍

问题来了：约束之间会互相打架。你把 a−b 拉对了，b−c 又歪了；把 b−c 修正好，a−b 又被拉长。解决办法简单粗暴 —— 把所有约束扫一遍，然后重复扫 N 遍：

for (let it = 0; it < iterations; it++)      // 典型 3 ~ 15
  for (const c of links)
    projectDistance(c);          // 每遍只用当前最新位置 → Gauss-Seidel

这叫 Gauss-Seidel 迭代：后面的约束立刻看到前面约束的修正结果，因此收敛比 Jacobi（先算完所有修正再统一应用）快得多。顺序敏感是它的代价 —— 同一条绳子，从左到右扫和从右到左扫，抖动形态会不一样，这也是布料左右不对称的根源之一。

Jakobsen 原文的关键洞察

碰撞约束和距离约束可以放进同一个松弛循环里。同一个框架，加一个"点必须在盒子内"的约束，就得到了箱子；加一个"点与点距离 ≥ r"，就得到了自碰撞；把链换成二维网格，就得到了布料 —— 代码一行都不用改。

05迭代次数决定刚性

这是 Verlet/PBD 最重要的工程事实：你调的不是刚度，是迭代次数。迭代越多 → 越接近"完全不可拉伸"；迭代越少 → 越像一根软橡皮筋。

下面是一条 26 节的铁链。拖动任意一个节点甩一甩，然后切换迭代次数，看读数里的"平均拉伸"：

鼠标（或手指）拖拽任意节点。颜色越红 = 那一节被拉得越长。迭代 ≤ 2 时铁链会像橡皮筋一样明显伸长。

把迭代次数拉到 1 再拖一下 —— 链条会像橡皮筋一样被拉长一大截，而且误差沿着链条往下累积：越靠近手抓的那一端越准确，越远越松。这就是"信息传播速度"问题。

图 5 · 松弛的传播：每次 pass 让修正信息向外扩散一格
PBD 的阿喀琉斯之踵

经典 PBD 的刚度参数 k 是依赖迭代次数和帧率的：同样 k = 0.5，跑 5 次迭代和跑 15 次的手感完全不同；把帧率从 60 改成 30，布料立刻变软。美术每次调整性能预算就得重调一遍参数 —— 这正是 XPBD 要解决的问题（第 12 节）。

06固定点、不等式与自碰撞

距离约束是"等于"，游戏里还有大量"小于等于"和"不许进"的需求。在 Verlet 框架里它们都是同一种操作：只在条件被违反时才投影。

约束类型数学形式触发条件典型用途
等式 · 距离|b − a| = d恒成立，总是投影绳子、布料结构线、骨骼
不等式 · 最小距离|b − a| ≥ d只在 dist < d 时自碰撞、防止膝盖穿模、体积保持
不等式 · 最大距离|b − a| ≤ d只在 dist > d 时限位绳、关节活动范围
单侧 · 平面(p − q)·n ≥ 0只在点越过平面地面、墙、碰撞体表面
钉住（pin）p = 目标点总是固定端、被玩家抓住的部位

投影代码只有一行判断的差别：

function solveMinDist(a, b, minD) {        // 不等式：只在太近时才推开
  const dx = b.x - a.x, dy = b.y - a.y;
  const d = Math.hypot(dx, dy) || 1e-6;
  if (d >= minD) return;                  // ← 与等式约束唯一的区别
  const diff = (d - minD) / d;
  const s = a.w + b.w; if (s === 0) return;
  a.x += dx * diff * (a.w / s); a.y += dy * diff * (a.w / s);
  b.x -= dx * diff * (b.w / s); b.y -= dy * diff * (b.w / s);
}

自碰撞：为什么布料不会穿自己

布料翻折时会自己穿过去，看起来像纸片一样诡异。最省事的解法是在粒子之间加最小距离约束。粒子对数量是 O(n²)，所以要么只对"可能靠近的对"加约束（用空间哈希做宽阶段），要么只在关键位置加 —— 比如 Jakobsen 的做法：在两个膝盖之间加一个不等式约束，腿就永远不会交叉。

工程取舍

完整自碰撞（每对粒子）在 300 粒子的布料上就是 4.5 万对 × 迭代次数，直接跪。实用做法是：粒子半径 + 空间哈希只检测真正接近的对，并且每帧只做 1 次自碰撞 pass（它不需要像结构约束那样高频收敛）。

角度约束：让关节别反折

用点积可以约束夹角：(b−a)·(c−b) / (|b−a||c−b|) ≥ cos θmax。但 Jakobsen 指出，更省事的做法是加一根"虚拟连杆"：在 a 和 c 之间加一个最大距离约束，就等价于限制了夹角 —— 又回到距离约束，复用同一套代码。

07绳子：悬链线是算出来的

把 N 个粒子串成链、锁住两端、交给重力 —— 它会自己停在一个特定形状上。没人写 cosh 公式，形状是从物理里长出来的。

那个形状叫悬链线

两端固定的链条，在自重下静止时的曲线是 y = a·cosh(x/a)，其中 a 由单位长度的重量与水平张力决定。它长得像抛物线但不是：

悬链线 catenary

载荷沿弧长分布 —— 链条自重就是这样，每一段绳子承担自己那一段的重量。

抛物线 parabola

载荷沿水平距离均匀分布 —— 悬索桥的桥面由竖直吊索挂载，才是抛物线。

图 6 · 重力 + 距离约束自然产生悬链线；两者差别很小，但在长跨度下肉眼可辨

一条绳子的最小实现

function makeRope(x, y, n, seg) {
  const pts = [], links = [];
  for (let i = 0; i < n; i++)
    pts.push({ x: x + i * seg, y, px: x + i * seg, py: y, w: i === 0 ? 0 : 1 });  // 首节点钉住
  for (let i = 0; i < n - 1; i++) links.push([pts[i], pts[i + 1]]);
  return { pts, links };
}
为什么绳子不该用弹簧再补一句

用"很硬的弹簧"模拟绳子，你需要：一个巨大的 k、一个配套的小 Δt、一堆阻尼调参，最后得到一根会抖、会伸长的橡皮筋。用距离约束，你只需要一个 rest 长度和一个迭代次数，得到的是一根真的不伸长的绳子，而且迭代越多越硬、帧率不变。

08布料：三类约束织成一张网

把链子排成二维网格，就得到了布料。但只加"相邻连线"的布料会像渔网一样软塌塌 —— 真实布料的抗剪切和抗弯折，靠的是另外两类约束。

图 7 · 布料的两类核心约束（第三类 bend = 隔一个节点的连线，画在下方代码里）
约束连接谁静止长度作用缺失后果
stretch 结构上下左右相邻spacing维持布面尺寸，承担张力布被拉长、像橡皮膜
shear 剪切两条对角线spacing·√2抵抗面内错切网格变成菱形，布"漏风"

for (let r = 0; r < rows; r++) for (let c = 0; c < cols; c++) {
  const p = at(r, c);
  if (c + 1 < cols) link(p, at(r, c + 1));           // stretch 横
  if (r + 1 < rows) link(p, at(r + 1, c));           // stretch 纵
  if (r + 1 < rows && c + 1 < cols) {               // shear 两条对角
    link(p, at(r + 1, c + 1));  link(at(r, c + 1), at(r + 1, c));
  }
  if (c + 2 < cols) link(p, at(r, c + 2));           // bend 横
  if (r + 2 < rows) link(p, at(r + 2, c));           // bend 纵
}

渲染小贴士

物理只需要粒子位置，渲染时才把它们连成三角/四边形网格。法线用相邻边的叉积现算，直接喂给 Mesh。绳索常用 LineRenderer 或按段生成胶囊体（capsule cylinder）；碰撞检测时，把每根"棍"当成带端帽的圆柱（capped cylinder）来处理。

09布娃娃：Hitman 的火柴人

初代《Hitman》的尸体不是刚体，是一堆粒子 + 距离约束组成的火柴人。这是 Verlet 最漂亮的一次亮相，也解释了为什么"布娃娃"这个词跟 Verlet 绑得这么紧。

图 8 · Hitman 式的粒子/连杆人形：渲染时由粒子位置反推骨骼朝向，物理上只是一条链

为什么不用刚体

  • 便宜：没有惯性张量、没有四元数积分、没有接触流形。10 个粒子比 10 个刚体快一个数量级。
  • 不会炸：约束是位置投影，最坏情况是"看起来有点软"，而不是"飞到天上"。
  • 够用：一具倒下的尸体，四肢绕自身轴的旋转根本看不出来 —— 省掉 60% 的自由度，视觉上几乎无损。

渲染时怎么摆姿势？由粒子位置反推：大腿方向 = normalize(膝 − 髋)，再用叉积补出一条正交轴构成旋转矩阵。膝盖和手肘的弯曲方向由上一帧的姿势决定（避免抽搐），这是 Jakobsen 特意提到的细节。

代价

连杆人形没有真实的转动惯量，所以不会自己翻滚得很好；也没有自碰撞体积，手会穿过身体。所以现代引擎（Havok、PhysX）回到刚体 + 关节约束，只是用类似的迭代投影求解器 —— Verlet 的思想留下来了，粒子模型退回到特效领域（头发、布料、软体）。

10投影式碰撞与摩擦

传统刚体引擎用冲量解决碰撞（算一个 J，改速度）。Verlet 里没有速度可改，所以走另一条路：把穿透的点推出来。这叫投影式响应。

惩罚力 vs 投影

惩罚力（penalty）

接触时施加一个排斥力。力太大 → 抖甚至炸；力太小 → 互相穿透。力的大小极难调，而且和刚度、质量、时间步全都耦合。

投影（projection）

直接把点移动到"最近的不穿透位置"。没有参数要调，永远不会炸，低速静止接触天然稳定 —— 代价是碰撞看起来"偏软"（因为恢复系数默认 0）。

三种最常用的碰撞体

// ① 地面 / 墙：单侧平面，最简单也最常用
if (p.y > groundY) {
  const vy = p.y - p.py, vx = p.x - p.px;
  p.y = groundY;
  p.py = p.y + vy * restitution;          // 反弹：下帧速度 = −e·vy
  p.px = p.x - vx * (1 - friction);      // 摩擦：切向速度打折
}

// ② 球 / 障碍物：沿法向推出
const dx = p.x - cx, dy = p.y - cy, d = Math.hypot(dx, dy);
if (d < R) { p.x = cx + dx / d * R;  p.y = cy + dy / d * R; }

// ③ 棍 vs 三角形（Hitman 的做法）：每根连杆当"带端帽的圆柱"
//    检测到穿透后，取穿透深度与接触点，把整根棍上的两个粒子按重心坐标推开
图 9 · 碰撞响应：粒子沿最短路径推出表面；连杆碰撞则把接触点按权重分给两端
摩擦在 Verlet 里的样子

改 px（上一帧位置）就是在改速度。地面摩擦 = px = x − vx·(1−μ)，μ 越大越黏。这也是"布料搭在球上不会滑下来"的实现方式 —— 完全不需要切向冲量那一套。

碰撞也要参与松弛

把碰撞放进每一轮松弛里，而不是"积分完做一次"。否则会出现：约束求解把点推回墙里 → 但你这一帧不再检测碰撞 → 渲染出一帧穿墙。顺序建议：

积分 → [ for it in 1..N: { 距离约束 → 自碰撞 → 环境碰撞 → 边界 } ] → 渲染

11固定步长、substep 与变步长

Verlet 的 a·Δt² 假设 Δt 恒定。一旦帧率波动，隐式速度 (x − x*)/Δt 就会把帧率抖动直接翻译成速度抖动 —— 布料会在掉帧时抽搐。三个手段，从推荐到不推荐。

① 固定步长 + 累加器（首选）

let acc = 0;
function frame(realDt) {
  acc += Math.min(realDt, 0.25);          // 防止卡顿后的"死亡螺旋"
  while (acc >= FIXED) { step(FIXED); acc -= FIXED; }
}

物理永远以 1/60 推进，渲染帧率多少都无所谓。渲染时可以对位置做插值消除轻微抖动。

② substep：同样预算，效果好得多

Macklin 等人 2019 年的《Small Steps in Physics Simulation》给了一个反直觉的结论：把一帧切成 8 个小步、每步只做 1 次约束迭代，比一帧做 8 次迭代效果好得多，开销完全一样。

1 步 × 8 次迭代

约束求解更"收敛"，但积分误差已经发生了：一次性走了大步，穿透更深、能量误差更大，迭代只是在收拾残局。

8 步 × 1 次迭代

每步都很小 → 线性化误差更小、穿透更浅、速度更新更及时。同样 8 次投影，稳定性提升显著。

dt_sub = dt / substeps for (s = 0; s < substeps; s++) { integrate(dt_sub); // 注意：a·dt_sub²，别写成 dt² for (it = 0; it < itersPerSub; it++) solveConstraints(); }

③ 变步长的补丁：Time-Corrected Verlet

如果非要跟着真实 dt 走，用 TCV 把速度按步长比例缩放：

x' = x + (x − x*) · (Δt_n / Δt_{n−1}) + a · Δt_n²

它能让不同帧率下的轨迹大致一致，但会破坏辛性质，长期能量表现不如固定步长。只在无法控制帧率的场合（比如网页里直接用 rAF 的 dt）作为折中。

推荐配置

固定 dt = 1/60，substeps = 4~8，每 substep 1~2 次约束迭代。布料迭代总量 8 左右就足够挺括；绳子 3~6 就够硬。遇到性能问题，先减粒子数，再减 substep，最后才减迭代。

12PBD 与 XPBD：给刚度一个物理量纲

经典 PBD 的刚度是"手感参数"，随迭代次数和帧率漂移。XPBD（Macklin 2016）引入柔度 α = 1/刚度，让刚度第一次变成了与帧率、迭代次数解耦的物理量。

α̃ = α / Δt² // 柔度按时间步归一化 Δλ = (−C − α̃·λ) / ( Σᵢ wᵢ|∇Cᵢ|² + α̃ ) // 拉格朗日乘子增量 Δxᵢ = wᵢ · Δλ · ∇Cᵢ // 位置修正 λ ← λ + Δλ // 每步开始清零，跨迭代累积

其中 C = |b − a| − rest 是约束违反量，∇C 是梯度（对距离约束就是单位方向向量）。对比一下：

经典 PBDXPBD
刚度表示k ∈ [0,1] 的修正比例柔度 α（单位 m/N），物理可解释
依赖迭代次数是 —— 迭代翻倍，材料变硬否 —— 迭代只影响收敛精度
依赖时间步是 —— 30 FPS 布料会变软否 —— α̃ = α/Δt² 已归一化
额外内存无每条约束一个 λ（每步清零）
α = 0 时—退化为完全刚性，等价于经典 PBD 的 k=1
要不要上 XPBD

如果你的布料只在一个固定帧率下运行、且参数是你自己调的，经典 PBD 完全够用，多写 20 行不划算。但如果：要支持可变帧率（移动端常见）、要暴露刚度给美术、要做软体/可形变材料 —— XPBD 是标准答案。Blender 的布料节点、现代软体求解器都走这条线。

还有更大的图景

  • 约束分组 / 图着色：把互不相连的约束染成同色，组内可并行 —— Gauss-Seidel 的顺序偏差也随之减轻。
  • 多层网格（multigrid）：在粗网格上先解一遍，让修正信息一步传遍整块布，解决第 5 节的传播速度问题。
  • warm starting：把上一帧的 λ 保留下来作为初值，收敛更快，特别适合悬挂类场景。

// ── 数据结构：一个粒子只存 4 个数 + 1 个逆质量 ──────────────────
const P = (x, y, w = 1) => ({ x, y, px: x, py: y, w });

// ── 积分：整个引擎的心脏，就这几行 ──────────────────────────────
function integrate(p, dt, gx, gy, damping) {
  const vx = (p.x - p.px) * damping, vy = (p.y - p.py) * damping;
  p.px = p.x;  p.py = p.y;
  p.x += vx + gx * dt * dt;
  p.y += vy + gy * dt * dt;
}

// ── 距离约束：等式（绳子/结构线）与不等式（自碰撞）合一 ─────────
function solveLink(a, b, rest, isMin = false) {
  const dx = b.x - a.x, dy = b.y - a.y;
  const d = Math.hypot(dx, dy) || 1e-6;
  if (isMin && d >= rest) return;          // 不等式：太近才推
  const s = a.w + b.w; if (s === 0) return;   // 两端都固定
  const diff = (d - rest) / d;
  a.x += dx * diff * (a.w / s);  a.y += dy * diff * (a.w / s);
  b.x -= dx * diff * (b.w / s);  b.y -= dy * diff * (b.w / s);
}

// ── 边界：投影 + 反弹 + 摩擦，全靠改 x / px ─────────────────────
function bounds(p, W, H, e = 0.3, mu = 0.15) {
  if (p.y > H) { const vy = p.y - p.py, vx = p.x - p.px;
                 p.y = H; p.py = p.y + vy * e; p.px = p.x - vx * (1 - mu); }
  if (p.x < 0) { p.x = 0; p.px = p.x + (p.x - p.px) * -e; }
  if (p.x > W) { p.x = W; p.px = p.x + (p.x - p.px) * -e; }
}

// ── 布料：三类约束一次建好 ─────────────────────────────────────
function makeCloth(ox, oy, cols, rows, sp) {
  const pts = [], links = [];
  const at = (r, c) => pts[r * cols + c];
  for (let r = 0; r < rows; r++) for (let c = 0; c < cols; c++)
    pts.push(P(ox + c * sp, oy + r * sp, (r === 0 && c % 3 === 0) ? 0 : 1));  // 顶边每隔 3 个钉住
  const L = (a, b) => links.push({ a, b, rest: Math.hypot(b.x - a.x, b.y - a.y) });
  for (let r = 0; r < rows; r++) for (let c = 0; c < cols; c++) {
    if (c + 1 < cols) L(at(r, c), at(r, c + 1));
    if (r + 1 < rows) L(at(r, c), at(r + 1, c));
    if (r + 1 < rows && c + 1 < cols) { L(at(r, c), at(r + 1, c + 1)); L(at(r, c + 1), at(r + 1, c)); }
    if (c + 2 < cols) L(at(r, c), at(r, c + 2));
    if (r + 2 < rows) L(at(r, c), at(r + 2, c));
  }
  return { pts, links };
}

// ── 主循环：固定步长 + substep ─────────────────────────────────
const DT = 1 / 60, SUB = 4, ITER = 2, GRAV = 1400, DAMP = 0.996;
let acc = 0;
function frame(realDt, cloth, W, H) {
  acc += Math.min(realDt, 0.25);
  while (acc >= DT) {
    const h = DT / SUB;
    for (let s = 0; s < SUB; s++) {
      for (const p of cloth.pts) integrate(p, h, 0, GRAV, DAMP);
      for (let it = 0; it < ITER; it++) {
        for (const l of cloth.links) solveLink(l.a, l.b, l.rest);
        for (const p of cloth.pts) bounds(p, W, H);
      }
    }
    acc -= DT;
  }
}

A调参表与踩坑清单

这些数字不是物理常数，是手感起点。单位按"1 米 = 100 像素、重力 ≈ 1400 px/s²"的尺度给。

参数典型值调大的效果调小的效果
damping 阻尼0.99 ~ 0.999更黏、更快静止（>1 会自激振荡！）更飘、晃个不停

七个一定会踩的坑

  1. 把 a·Δt² 写成 a·Δt —— 加速度效果和帧率挂钩，改帧率手感全变。
  2. 忘记初始化 px/py —— 第一帧速度为 0 或翻倍，物体"跳"一下才动。
  3. 除以零 —— 两点重合时 d = 0，或者两个固定点（w 之和为 0）。都要保护。
  4. damping > 1 —— 每帧注入能量，几秒后必炸。阻尼永远 ≤ 1。
  5. 一帧只做一次碰撞检测 —— 约束求解会把点推回墙里，必须把碰撞放进松弛循环。
  6. 直接用 rAF 的真实 dt 积分 —— 切后台再回来会瞬移。要固定步长 + 累加器 + clamp。
  7. 改了位置却没同步 px —— 拖拽物体时如果只设 x 不改 px，松手瞬间会获得巨大速度（有时这正是你想要的手感，但要知道自己在干什么）。
调试心法

Verlet 出问题时，先关掉所有约束看纯积分是否正常，再逐个加回约束；把 iterations 拉到 50 看问题是"不收敛"还是"模型本身错了"；把 gravity 设 0 看是不是重力放大了误差。三步能定位 90% 的诡异行为。
